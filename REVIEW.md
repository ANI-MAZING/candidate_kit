# REVIEW.md

Line numbers refer to the **original starter** `app/main.py`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` L22 | Default client returns **naive** datetimes, so stored UTC instants get mixed with local/IST arithmetic, and comparing them with aware datetimes raises `TypeError`. | `punch_out - punch_in` with an aware value → 500. | `MongoClient(..., tz_aware=True, tzinfo=utc)`; every instant is an aware UTC datetime and is converted to epoch ms only at the API boundary. |
| 2 | `compute_late_minutes` L35 | `punch_in.replace(hour=h, minute=m)` sets the shift start in the punch's own zone (UTC/server-local), not IST. | Shift 09:30 IST, punch 09:28 IST (03:58 UTC) → start becomes 09:30 **UTC**, so the punch looks 5½ h early. A 10:05 IST punch → 0 late instead of 35. | The shift start instant is built in IST from the record's attendance date (`shift_bounds`). |
| 3 | `compute_late_minutes` L37 | The grace check runs on **floored** minutes (`> 10`), so anything from 10:01 to 10:59 after the start counts as on time. R2 says strictly more than 10:00. | 09:40:01 → `int(10.01)` = 10, and `10 > 10` is false → 0 (expected 10). | Compare **seconds** (`> 600`), then floor to minutes. |
| 4 | `compute_late_minutes` | Overnight shifts are ignored: a 01:00 punch on a 22:00 shift is measured against the same day's 22:00 → negative/0. Seconds are never truncated. | Overnight shift 22:00-06:00, punch 01:00 → 0 (expected 180). | Lateness is measured from `shift_start` on the R1 attendance date. Instants are truncated to whole seconds on input. |
| 5 | `compute_work_hours` L41 | `round()` is float rounding (round-half-even on the binary value), not half-up (R4). | 4 h 29 m 42 s = 4.495 h → `round()` gives 4.49 (and `half_day` flips to true); expected 4.50. 18 s = 0.005 → 0.0, expected 0.01. | Integer seconds / 3600 in `Decimal`, `quantize(0.01, ROUND_HALF_UP)`. |
| 6 | `compute_overtime` L44-47 | No 30-minute threshold (R3). The shift end is not moved to the next day for overnight shifts. Overnight 06:40 next day → huge negative→0 or a crash. | `shift_bounds` adds a day for overnight shifts. Floor minutes, counted only if ≥ 30. |

| 11 | `create_employee` L82, L85 | `created_at = datetime.now()` is naive **server-local** time, which PyMongo stores as if it were UTC (off by +5:30 on an IST server). | 16 | `punch_in` L102 | `datetime.fromtimestamp(ms/1000)` gives naive **server-local** time (and keeps milliseconds). ### Looked at and decided were **not** defects
- `load_dotenv()`: its default `override=False` means real environment variables already take priority over `.env`, as required.
- `IST = timezone(timedelta(hours=5, minutes=30))`: correct. India has no DST, so a fixed offset is right.
- Sync (`def`) endpoints with PyMongo: FastAPI runs them in a threadpool, and `MongoClient` is thread-safe and pooled. There's no need to switch to Motor.
- `doc.pop("_id")` after `insert_one` in `create_employee`: correct (`insert_one` mutates the dict). I replaced it anyway with an explicit serializer.
- The helper *signatures* were reused in spirit, but `compute_late_minutes`/`compute_overtime` now take the shift instants (built by `shift_bounds`) instead of `"HH:MM"` strings, because a time of day alone can't express "IST on the attendance date, next day for overnight".
